## 목적

테스트 파일을 **리뷰 회차·이슈 번호가 아니라 기능 기준으로 찾을 수 있게** 정리할지 팀에서 정한다. 이 이슈는 **논의용**이다. 코드 변경은 합의 후 별도 이슈로 만든다.

## 배경

- 테스트 파일 37개 중 일부는 이름이 기능이 아니라 작업 이력을 따른다: `test_etf_review_round2.py`, `test_explain_review_fixes.py`, `test_etf_tax_wrong_note.py`, `test_etf_tax_quote_punctuation.py` 등.
- `test_forbidden_retry.py`는 1,600줄이 넘는다.
- 일부 테스트는 **잠긴 수용 테스트**다(`pyproject.toml` 주석, `test_etf_review_round2.py` docstring: "잠긴 테스트는 건드리지 않고 새 파일에 둔다"). 그래서 기존 파일을 고치지 않고 새 파일을 계속 추가하는 방식으로 늘어났다.
- 결과적으로 "세금 단서 관련 테스트가 어디 있지?"를 찾으려면 파일 여러 개를 열어야 한다.

## 정할 것

1. **잠긴 테스트의 범위**: 어떤 파일이 잠겨 있는지 목록으로 확정한다. 잠금의 목적(요구사항 고정)과 파일 이동이 충돌하는지 본다. 파일 이동·이름 변경은 테스트 내용을 바꾸지 않는다.
2. **폴더 구조 안**: 예시
   ```
   tests/
     unit/        # 순수 함수 (conditions, number_check, copy, chunker)
     agent/       # ChatAgent 흐름 (재시도, 인용, 범위 밖)
     guardrails/  # 금지 표현, 내부 누출, 종목 추천
     etf/         # ETF 코드 필터, 세금 단서, 종목명 교정
     integration/ # calc 클라이언트, RAG 검색
     scenarios/   # (기존 유지)
   ```
3. **앞으로의 규칙**: 새 테스트를 추가할 때 이슈 번호가 아니라 기능 폴더·파일에 넣고, 이슈 번호는 docstring에만 적는다.
4. **큰 파일 분할**: `test_forbidden_retry.py`를 사유별(종목 추천, 내부 키, 상품명 등)로 나눌지.

## 합의 후 작업 시 제약 (별도 이슈에 옮길 내용)

- 테스트 **내용(assert, 입력)은 바꾸지 않는다.** 파일 이동과 분할만 한다.
- 이동 전후 `uv run pytest --collect-only -q | wc -l`로 수집되는 테스트 수가 같아야 한다.
- `tests/fakes/`의 경로 계산(`Path(__file__).resolve().parents[3]`)처럼 위치에 의존하는 코드가 깨지지 않는지 확인한다.

## 참고 개념

- **테스트도 응집도를 따진다**: 같은 기능을 검증하는 테스트가 한곳에 있어야, 기능을 바꿀 때 어떤 테스트가 영향받는지 바로 안다. 이력 기준 파일명은 "언제 추가했는지"는 알려 주지만 "무엇을 검증하는지"는 알려 주지 않는다.
- **pytest 수집 규칙**: pytest는 `test_*.py` 파일과 `test_` 함수를 자동으로 찾는다. 하위 폴더에도 `__init__.py`가 있으면 패키지로 인식해, 같은 이름의 테스트 파일이 다른 폴더에 있어도 충돌하지 않는다.
- **수용 테스트 잠금**: 요구사항을 고정한 테스트를 잠그는 건 AI 에이전트가 테스트를 고쳐서 통과시키는 걸 막는 좋은 장치다. 정리 작업이 이 장치를 약하게 만들지 않도록, 잠금 규칙을 파일 단위가 아니라 폴더나 마커(`@pytest.mark.locked`) 단위로 옮기는 방법도 논의할 수 있다.
