# A-2 계획·인증 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 데모 계정 로그인부터 목표·자금 입력, 내 계획 저장·적용·되돌리기, 결과 화면의 조건 바·면책 문구까지 A-2 범위를 백엔드(auth, plan 모듈)와 프론트(로그인·입력·결과 뼈대)로 구현한다.

**Architecture:** 백엔드는 Spring Security OAuth2 Resource Server로 HttpOnly 쿠키의 HS256 JWT를 검증하고, plan 모듈이 `rules.yml` 하나를 원본으로 입력을 검증·저장한다. 프론트는 `GET /api/input-rules`로 같은 규칙을 받아 즉시 검증하고, 모든 API를 `credentials: "include"` fetch로 부른다. 금액 계산은 하지 않는다.

**Tech Stack:** Java 21, Spring Boot 4.1, Spring Modulith 2.1, Spring Security Resource Server(Nimbus), JPA, PostgreSQL 16 / Vite, React 19, TypeScript strict, Tailwind 4, Vitest + Testing Library

**Spec:** `docs/superpowers/specs/2026-11-16-a2-plan-auth-design.md`

## Global Constraints

- 커밋은 사용자 지시가 있을 때만 한다. 각 태스크의 "Commit" 단계는 **변경 파일을 정리해 두는 단계**로 읽고, 사용자가 허락하면 그때 커밋한다. 작업 브랜치는 `develop`에서 `feat/a2-plan-auth`.
- 백엔드: 네이버 컨벤션(스페이스 4칸, 120자), `./gradlew checkstyleMain checkstyleTest` 통과. 모듈 `auth`, `plan`은 `allowedDependencies = {}` 유지, `ModularityTests` 통과. H2 금지, DB 테스트는 `@Import(TestcontainersConfig.class)`.
- 엔드포인트마다 REST Docs 테스트(`docs/HealthDocsTest` 패턴). 태그: `Auth`, `Plan`.
- `memberId`는 JWT subject에서만 얻는다(`@AuthenticationPrincipal Jwt jwt` → `Long.valueOf(jwt.getSubject())`).
- **금액 단위: DB와 API는 원(KRW, long). 화면 입력·표시는 만원.** 서버는 금액이 10,000의 배수가 아니면 `NOT_UNIT` 오류.
- 금리는 `BigDecimal`, 소수 둘째 자리까지(셋째 자리 이상이면 `INVALID_SCALE`).
- 화면 문구에 '추천'을 긍정형으로 쓰지 않는다. 해요체, 면책 문구만 격식체.
- 프론트: TypeScript strict, `any` 금지, 시맨틱 HTML·키보드 조작, 새 컴포넌트·유틸에는 테스트. `npm run lint && npm run type-check && npm run test:run` 통과.
- 쿠키 이름 `MOEUN_TOKEN`, HttpOnly, SameSite=Lax, Path=/, Secure는 `moeun.jwt.cookie-secure`(로컬 false).
- JWT 만료 30분, 기존 설정 `moeun.jwt.{secret, access-token-ttl, issuer}` 사용.
- API 기본 주소: 프론트 환경변수 `NEXT_PUBLIC_API_BASE_URL`(기본 `http://localhost:8080`).

## Review Focus

1. **입력 중 세션 만료**: 30분 뒤 "결과 보기"를 누르면 401 → 로그인 화면으로 가고 "로그인 시간이 지나 다시 로그인해 주세요." 안내. 입력값은 잃어도 되지만 조용히 실패하면 안 된다. → Task 8(apiFetch 401 처리), Task 10(제출 401)
2. **붙여 넣은 금액 형식**: "1,000", " 120 ", "1.5", "-5", "１２０"(전각)을 넣었을 때 쉼표·공백은 허용해 정규화하고, 소수·음수·숫자 아님은 칸 오류. → Task 9 `parseManwon` 테스트
3. **결과 보기·적용 두 번 클릭**: 요청 중 버튼 비활성화로 한 번만 전송. 서버는 revision 불일치 409. → Task 5(409), Task 10·11(버튼 disabled)
4. **오래된 화면에서 적용·되돌리기**: 다른 탭에서 계획을 바꾼 뒤 적용·되돌리기를 누르면 409 → "그사이 계획이 바뀌었어요" 토스트 + 최신 계획으로 갱신. 되돌리기를 두 번 눌러도 두 번째는 409. → Task 5, Task 11
5. **직접 입력 목표명 경계**: 공백만, 100자 초과, 이모지가 섞인 100자. 서버와 프론트 모두 앞뒤 공백 제거 후 **코드 포인트 수**로 센다. → Task 3, Task 9

## 스펙과 다르게 정한 것 (실행 전 확인)

- **문구 파일**: 스펙은 저장소 루트 `copy/copy.ko.yml` 공용 파일을 A-2가 만든다고 했지만, 프론트에서 YAML을 읽으려면 의존성과 빌드 경로 문제가 생긴다. 이 계획은 `frontend/src/copy/ko.ts`에 둔다. B팀이 같은 문구를 쓸 때 공용 파일로 옮긴다.
- **재발급 구현**: `moved-to-code.md`의 `TokenRenewalFilter` 대신 `@SkipRenewal`을 읽을 수 있는 `TokenRenewalInterceptor`(HandlerInterceptor)로 만들고 문서 이름을 고친다.

- **기준 시나리오 변경 API**는 이 계획에 넣지 않는다(UI 위치 미확정, TBD-40). 계산 담당이 필요할 때 `ConditionOverride`에 필드를 추가한다.
