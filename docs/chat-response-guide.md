# 대화 응답 기준표 (초안)

> 상태: **초안(#249)**. 팀 확인 전이다. 맨 아래 "팀 확인 필요"에 답이 정해지면 초안 표시를 뗀다.

결과 화면 오른쪽 AI 대화에서 **누가 무엇을 말하는지** 정한다. 프롬프트(`ai-server/app/llm/prompts.py`), 응답 보정(`assemble.py`), e2e 시나리오(`scripts/e2e/test_12_conversation.py`), 리뷰가 이 표를 기준으로 한다. 사례마다 프롬프트를 고치지 않고 이 표를 먼저 고친다.

## 원칙

1. **한 가지 말은 한 곳에서만 한다.** 화면이 고정으로 고지하는 내용은 AI 본문에 다시 쓰지 않는다.
2. **반드시 나가야 하는 문장은 코드가 보장한다.** 정책상 빠지면 안 되는 문장은 모델에게 맡기지 않고 화면이나 서버가 문구표 문장 그대로 낸다.
3. **AI 본문은 질문에 대한 답만 한다.** 묻지 않은 항목, 다른 조건을 바꿔 보라는 권유, 고지 반복은 쓰지 않는다.
4. **숫자는 서버 값만 인용한다(NFR-INT-01).** 길이 규칙은 인용 규칙보다 앞서지 않는다.

## 1. 화면이 고정으로 고지하는 것 — AI 본문에 쓰지 않는다

| 내용 | 문구표 키 | 위치 | AI 본문 |
|---|---|---|---|
| 모의 계산이며 수령액·수익을 보장하지 않음, 상품 가입 권유 아님, 환율 미반영, 투자 판단은 본인 책임, AI 설명은 참고용 | `disclaimer` | 결과 화면 맨 아래(`Disclaimer.tsx`), 대화 패널 하단(`ChatWindow`) | **쓰지 않는다.** "보장하지 않아요", "추정이라 수익을 약속하지 않아요", "참고용이에요" 같은 같은 뜻의 문장도 포함. 사용자가 수익을 직접 물어도 본문에 쓰지 않는다(Q1 확정) |
| 세 가지 경우는 과거 데이터를 나눈 시나리오이며 예측이 아님 | `result.scenarioNotice` | 3구간 카드 아래(`ScenarioCards.tsx`) | **쓰지 않는다** |
| 세금은 일반 과세 기준 가정, 세법이 바뀌면 달라짐, 전문가 확인 | `tax.note`, `tax.noteEtfTaxFree` | 가정 보기(`AssumptionsSection.tsx`), 계획에 맞는 하나(#233) | **쓰지 않는다.** 서버가 지운다 |
| 이미 목표를 넘은 계획(보유 자산 ≥ 목표) | `result.alreadyExceeded`(화면), `chat.alreadyExceeded`(대화 첫 줄) | 결과 요약 자리, 대화 패널 첫 줄 | 서버 고정 문장으로만 낸다(아래 2절) |

## 2. 서버가 붙이거나 대신 내는 문장 — 모델이 쓰지 않아도 나간다

| 상황 | 문구표 키 | 동작 | 코드 |
|---|---|---|---|
| 목표 금액을 바꾼 비교 | `chat.goalAmountChangedNote` | 본문 뒤에 붙인다 | `assemble.py` |
| 바꾼 조건으로 적용하면 이미 목표 초과 | `chat.changedAlreadyExceeded` | 본문 뒤에 붙인다 | `assemble.py` |
| 범위 밖 질문 | `outOfScope` + 바꿀 수 있는 조건 이름 | 본문을 이 문장으로 바꾼다 | `assemble.out_of_scope_content` |
| 세제 혜택·절세 질문 | `outOfScope.tax` | 이 문장만 낸다 | 프롬프트 + `assemble.py` |
| 목표 종류·보유 자산 등 대화로 못 바꾸는 조건 | `chat.unchangeableCondition` | 이 문장만 낸다 | `agent._FIXED_COPY_KEYS` |
| 계획 없음 | `chat.noPlan` | 이 문장만 낸다 | `agent._FIXED_COPY_KEYS` |
| 초과 계획에서 조건 변경 | `chat.alreadyExceeded` | 이 문장만 낸다 | `agent._FIXED_COPY_KEYS`, `context.py` |
| 답을 만들지 못함 | `chat.failed` | Spring이 FAILED 메시지로 저장 | backend `ChatAnswerListener` |
| 근거 출처 | (문구 아님) | 출처 목록을 본문 아래 따로 보인다 | `citation_chunk_ids` → 프론트 `Citations` |

## 3. 메시지 종류별 AI 본문 기준

| 종류 | 언제 | 말할 것 | 말하지 않을 것 | 길이 상한 |
|---|---|---|---|---|
| **값 조회** (ANSWER) | "적금 금리 몇이야?", "월 저축액 얼마야?" | 그 값 하나(display 문자열 그대로) | 기준 월, 세율, 가정, 바꿔 보라는 권유 | 1문장 |
| **수익 질문** (ANSWER) | "수익이 얼마나 나요?", "수익률은?" | 연 수익률 숫자는 없다는 것, 결과는 좋았던 때·평균·나빴던 때 세 경우로 본다는 것 | 수익 약속·보장 여부(1절 `disclaimer`), 수익률 숫자 | 2문장 |
| **개념·위험 설명** (ANSWER) | "ETF가 뭐야?", "나스닥 ETF 위험은?" | 질문한 개념, 근거 문서 내용 | 내 계획 숫자(묻지 않았으면), 1절 고지 | 3문장 |
| **결과 설명** (EXPLANATION) | 결과 화면이 뜰 때 자동 | 평균 기준 결과와 목표 대비, 달성 여부(세 경우가 같으면 한 번에) | 입력 조건 나열(목표 금액·기간·월 저축액·비중·금리·종목은 화면 위 조건 바에 있다, Q3 확정), 1절 고지, 좋았던·나빴던 때 각각의 시점 나열 | 3문장 |
| **조건 변경 결과** (RECALC_RESULT) | "월 150만원이면?" | 무엇을 바꿨는지, 평균 기준 결과 변화 | 바꾸지 않은 조건, 다른 시나리오 세부(비교 카드에 있음), 1절 고지 | 2문장 (+2절 서버 문장) |
| **되묻기** (CLARIFY) | 값·조건·단위가 모호 | 무엇을 정해 달라는지 한 가지 | 예시 금액·금리·기간을 지어내기 | 1문장 |
| **범위 밖** (OUT_OF_SCOPE) | 개별 주식, 코인, 세제 혜택 등 | 모델 본문 없음 | — | 2절 문장만 |
| **아직 없는 기능** (ANSWER) | "ETF를 나스닥으로 바꿔줘"(#154 전) | 지금은 못 한다는 사실과 할 수 있는 것 | 곧 된다는 약속 | 2문장 |

공통: 쉬운 말, 전문 용어는 처음에 짧게 풀기, 결과를 보장하거나 단정하지 않기(단, 1절 고지 문장을 덧붙이는 방식으로 하지 않는다).

## 4. 지금 구현과 어긋나는 곳 (후속 작업)

| # | 어긋남 | 근거 | 후속 |
|---|---|---|---|
| 1 | 프롬프트 `## 말투`가 "과거 데이터 기반 추정임은 계산 결과를 설명할 때 한 번만 밝힙니다"라고 해서 결과 설명마다 끝에 고지가 붙는다 | 1절 `disclaimer` 중복 | 프롬프트에서 지우고 1절 목록을 "쓰지 않는다"로 옮긴다 |
| 2 | 프롬프트의 수익률 질문 규칙이 "과거 데이터로 만든 구간이며 수익을 약속하지 않아요"라고 답하게 한다 | Q1 확정: 수익을 물어도 약속 여부는 본문에 쓰지 않는다 | 프롬프트를 3절 "수익 질문" 행대로 바꾼다 |
| 3 | EXPLANATION 상한이 프롬프트에는 4문장이고 입력 조건 나열을 막지 않는다. `EXPLAIN_INSTRUCTION`도 "어떤 조건으로 계산했는지" 설명하라고 한다 | 실제 답이 조건 나열 1문장 + 결과 2문장 + 고지 1문장. Q3 확정: 조건 나열을 뺀다 | 프롬프트 상한을 3문장으로, `EXPLAIN_INSTRUCTION`에서 조건 설명 요청을 뺀다 |
| 4 | e2e가 세금 안내만 금지 문장으로 검사한다 | 1절 전체가 대상 | `test_12_conversation.py`에 1절 금지 문장 목록(`disclaimer`의 핵심 구절, `scenarioNotice`)을 추가하고 EXPLANATION 길이 검사를 넣는다 |
| 5 | 1절의 "같은 뜻의 문장"은 글자 비교로 다 막을 수 없다 | 모델이 말을 바꿔 쓴다 | 서버에서 막을지(문장 삭제) 프롬프트+e2e 측정으로 둘지 Q2 |

## 5. 이 표를 바꾸는 방법

새 고지 문구나 서버 고정 문장이 생기면 같은 PR에서 함께 고친다.

1. 문구표(`copy/copy.ko.yml`)에 키를 더한다.
2. 이 표의 1절 또는 2절에 한 줄을 더한다(키, 위치, AI 본문 규칙).
3. 1절이면 프롬프트 "말하지 않을 것"과 e2e 금지 문장 목록에 더한다. 2절이면 붙이는 코드와 그 테스트를 더한다.
4. 메시지 종류별 기준(3절)을 바꾸면 프롬프트의 `## 답의 범위와 길이`와 e2e 길이 검사를 같이 고친다.

- **Q2.** 1절과 같은 뜻의 문장을 모델이 말을 바꿔 쓰면 서버가 지울지(코드 규칙, 오탐 위험), 프롬프트와 e2e 측정으로만 관리할지.
